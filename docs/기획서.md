# SafeCert 기획서

평면도를 올리면 현행 소방 법령에 맞는지 도면 위에 색으로 표시하고, 사람이 항목마다 확인한 뒤, AI 가 쓴 설명을 담은 검토 보고서(PDF)로 내보내는 iPad 앱.

## 기획의도

- **흩어진 기준을 한곳에:** 법·시행령·시행규칙·소방청 고시에 나뉜 비상구 기준을 매일 모아, 올린 도면에 바로 적용하도록 합니다.
- **반복 업무 절감:** 도면을 기준과 하나하나 대조하고 보고서를 따로 쓰던 일을 자동 판정과 보고서 작성으로 줄여, 확인과 판단에 집중하도록 합니다.
- **법령 변경 누락 방지:** 매일 현행 법령을 확인해 판정 기준에 반영하고, 기준이 바뀐 항목은 따로 표시해 놓치지 않도록 합니다.
- **인명·재산 보호:** 문을 열기 전 설계 단계에서 비상구 위치·크기 문제를 찾아 고치도록 해, 화재 때 대피할 길을 확보합니다.

## 결과물의 핵심 포인트

- 도면 검토 결과로 보고서 자동 작성
  - 판정 항목의 위치·대상·읽은 값·기준을 보고서에 자동 연결.
  - 검토자 확인 여부와 AI 설명을 담은 PDF 보고서 생성.
- 법령 변경을 판정 기준에 반영
  - 소방 관련 법과 고시가 바뀌면 자동 검증을 거쳐 판정 기준을 갱신하고, 검증을 통과하지 못한 변경은 표시만 하고 반영하지 않음.
  - 향후에는 바뀐 기준의 영향을 받는 기존 검토를 찾아 다시 판정하도록 확장.
- 검토자 확인 후 보고서 발행
  - 법 위반 여부를 단정하지 않고, 확인이 필요한 항목과 근거 조문을 제시.
  - 항목마다 검토자가 확인 체크한 뒤 보고서로 내보내며, 확인 여부와 시각을 보고서에 표시.

## MVP 범위

**PDF 도면 올리기 → 현행 법령 기준 충족 여부를 도면 위에 색으로 표시 → 사람이 항목마다 확인(체크) → PDF 보고서로 내보내기**

## 1. 문제

- 노래연습장·PC방·음식점 같은 **다중이용업소**는 문을 열기 전에 비상구 위치·크기 등 소방 안전 기준을 지켜야 함
- 기준이 법·시행령·시행규칙·소방청 고시에 나뉘어 있고, 수시로 바뀜
- 설계 단계에서 놓치면 허가 단계에서 보완 요구 → 다시 설계·공사 → 개업 지연
- 지금은 전문가가 도면을 하나하나 눈으로 확인

## 2. 대상 사용자

| 사용자 | 쓰는 장면 |
|---|---|
| 인테리어·설계 실무자 | 도면 제출 전 스스로 사전 점검 |
| 소방시설 업체 | 의뢰받은 도면의 1차 확인 |
| 다중이용업소 창업 예정자 | 계약·공사 전 도면의 위험 확인 |

## 3. 해결 방법

1. 도면(PDF) 올리기
2. 앱이 벽·문·출입구·축척을 자동으로 읽음 → 사용자가 확인
3. **오늘 날짜의 법령** 기준으로 판정 → 도면 위에 색으로 표시
4. 사람이 판정 항목마다 내용을 보고 **확인 체크** → 도면 표식에도 체크 표시
5. 검토 보고서(PDF) 내보내기 → 확인 여부 · AI 가 쓴 쉬운 설명 포함 → 공유

| 색 | 뜻 |
|---|---|
| 빨강 | 의무 미충족 |
| 주황 | 위반 가능성 · 확인 필요 |
| 노랑 | 법령 변경 영향 |
| 초록 | 확인 범위 안에서 기준 충족 |
| 회색 | 자료 부족 · 대상 아님 |

## 4. AI 활용 방식

| 어디에 | 무엇을 | 방식 |
|---|---|---|
| 검토 보고서 | 요약 · 판정별 설명 · 보완 방향 문장 작성 | 생성형 AI(Google Gemini) |
| 근거 찾기 | 판정마다 관련 법 조문 찾기 | RAG(관련 자료를 먼저 찾아 AI 에 함께 주는 방식) |
| 법령 최신화 | 매일 법령 수집·검증 | 자동화 워크플로우 |
| 도면 글자 | 도면 이미지 속 글자 읽기 | 이미지 인식 AI(Apple Vision) |

원칙

- **판정은 AI 가 하지 않음** — 정해진 계산 규칙이 판정 → 같은 도면이면 언제나 같은 결과, 근거를 끝까지 따라갈 수 있음
- **AI 는 설명만** — AI 문장을 판정 결과와 하나하나 대조해, 사실과 다른 숫자·표현이 있으면 자동으로 뺌
- **최종 확인은 전문가** — 모든 결과에 「감수 전 · 참고용」 표시

## 5. 기술 선택과 이유

| 영역 | 사용 기술 | 이유 |
|---|---|---|
| 앱 | iPad 앱(Swift · SwiftUI) | 도면을 크게 보고 손으로 확대 — 태블릿이 알맞음 |
| 저장 | 기기 안 저장(SwiftData) | 도면은 고객 자료 → 서버에 올리지 않음 |
| 도면 읽기 | 애플 기본 PDF 분석 · 글자 인식(Vision) | 별도 프로그램 없이 기기 안에서 처리 |
| 법령 | 국가법령정보 공동활용 Open API | 정부 공식 원문, 매일 최신 |
| 생성형 AI | Google Gemini API(무료 등급) | 시연 규모에서 비용 없음 · 한국어 문장 · 정해진 형식(JSON) 응답 지원 |
| 보고서 | 애플 기본 기능으로 PDF 직접 생성 | 서버 없이 기기에서 바로 만들고 공유 |
| 배포 | TestFlight | 애플 공식 테스트 배포 — 링크로 설치 |
